The System Design Primer — Study Path Module 15.2

Design a least-recently-used (LRU) cache

A fixed-capacity cache that, once full, evicts whichever entry hasn't been touched the longest — while keeping both lookup and eviction at O(1).

The problem

A plain dict gives you O(1) get/set, but no sense of "oldest" or "newest." A plain linked list gives you ordering, but finding an item in it means scanning. An LRU cache needs both at once: instant lookup and instant re-ordering by recency. The classic answer is to combine them.

Classes at a glance

  • NodeOne cache entry, living inside the linked list. Holds the cached results.
  • LinkedListTracks recency order. The front is "most recently used," the tail is "least recently used" — the next thing to evict.
  • CacheThe public API. Pairs a lookup dict (query → node) for instant access with the LinkedList for instant re-ordering.

Key design decisions

  • Hash map + doubly linked list is the whole trick. The dict gives O(1) "does this key exist, and where." The linked list gives O(1) "move this to the front" and "drop whatever's at the tail" — neither structure alone can do both jobs cheaply.
  • On a hit, move to front. get() and the update branch of set() both call move_to_front — touching an entry is what "recently used" means.
  • On a miss at capacity, evict from the tail first. set() checks self.size == self.MAX_SIZE; if full, it removes the tail node from both the list and the lookup dict before inserting the new entry — forgetting the dict side of an eviction is the most common bug in a real interview attempt.
Read this before you trust the code as-is: this sample is intentionally a skeleton, and it's worth noticing exactly where. The three LinkedList methods (move_to_front, append_to_front, remove_from_tail) are all stubbed with pass — they describe the shape of the solution an interviewer wants sketched, not a finished implementation. And Node.__init__ has a real bug: self.next = next accidentally assigns Python's built-in next() function instead of initializing an empty link — it should be self.next = None, plus a self.prev = None (a doubly linked list needs a previous pointer too, or you can't splice a node out of the middle in O(1)). Spotting that kind of thing is exactly the sort of close reading an interviewer rewards.

class Node(object):

    def __init__(self, results):
        self.results = results
        self.next = next


class LinkedList(object):

    def __init__(self):
        self.head = None
        self.tail = None

    def move_to_front(self, node):
        pass

    def append_to_front(self, node):
        pass

    def remove_from_tail(self):
        pass


class Cache(object):

    def __init__(self, MAX_SIZE):
        self.MAX_SIZE = MAX_SIZE
        self.size = 0
        self.lookup = {}  # key: query, value: node
        self.linked_list = LinkedList()

    def get(self, query):
        """Get the stored query result from the cache.

        Accessing a node updates its position to the front of the LRU list.
        """
        node = self.lookup.get(query)
        if node is None:
            return None
        self.linked_list.move_to_front(node)
        return node.results

    def set(self, results, query):
        """Set the result for the given query key in the cache.

        When updating an entry, updates its position to the front of the LRU list.
        If the entry is new and the cache is at capacity, removes the oldest entry
        before the new entry is added.
        """
        node = self.lookup.get(query)
        if node is not None:
            # Key exists in cache, update the value
            node.results = results
            self.linked_list.move_to_front(node)
        else:
            # Key does not exist in cache
            if self.size == self.MAX_SIZE:
                # Remove the oldest entry from the linked list and lookup
                self.lookup.pop(self.linked_list.tail.query, None)
                self.linked_list.remove_from_tail()
            else:
                self.size += 1
            # Add the new key and value
            new_node = Node(results)
            self.linked_list.append_to_front(new_node)
            self.lookup[query] = new_node
