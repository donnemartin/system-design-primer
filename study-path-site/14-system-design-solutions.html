MODULE 14

System Design Solutions

Eight classic system design interview questions, worked end to end using the Module 01 framework (use cases → high-level design → core components → scaling). Try each one yourself in Module 13's exercises first — these are the answer key, not the starting point.

  1. 14.1
    Pastebin

    A url-shortener-shaped problem: generate a short link, store the paste, serve it back fast.

  2. 14.2
    Twitter timeline & search

    The fanout problem — getting one tweet in front of thousands of followers without melting the database.

  3. 14.3
    Web crawler

    Crawl a billion links without looping forever, then serve search results from what you indexed.

  4. 14.4
    Mint.com

    Link a bank account, pull transactions asynchronously, categorize them, and track a budget.

  5. 14.5
    Social graph

    Shortest path between two people, sharded across machines — deliberately without a graph database.

  6. 14.6
    Query cache

    An LRU cache for search results — the same data structure you'll build from scratch in Module 15.

  7. 14.7
    Amazon sales rank

    A two-step MapReduce job that turns raw transactions into a per-category leaderboard.

  8. 14.8
    Scaling to millions on AWS

    The odd one out — this is the only solution that walks the benchmark → profile → fix → repeat loop itself, stage by stage, instead of jumping to the final diagram.

Every solution above reuses vocabulary from Modules 02–11 (CAP, caching, sharding, replication, async, REST/RPC) instead of re-explaining it — if a term feels unfamiliar, it's worth a detour back to that module before continuing.
